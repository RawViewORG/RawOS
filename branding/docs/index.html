RawOS Documentation

RawOS is a malware reverse-engineering workstation built around RawView. It ships a curated toolkit for dissecting binaries, an isolated environment for detonating samples, and Wine for Windows/PE work, all on an Ubuntu base with an XFCE Tokyo Night desktop.

Handle malware with care. Only run live samples inside an isolated VM using the rawos-isolated network. Snapshot before you detonate, and keep real network access off. RawOS makes this safer, but it does not make careless handling safe.

About RawOS

RawOS bundles everything an analyst needs to go from a raw sample to a finished report without hunting for tools or configuring Ghidra by hand:

  • RawView preinstalled, with Ghidra 12 and a Temurin JDK already wired up.
  • A static, dynamic, and network analysis toolkit (see The toolkit).
  • Virtualization tooling (QEMU/KVM, libvirt, virt-manager) plus an isolated detonation network.
  • Wine for running and debugging Windows binaries.
  • A safe-by-default firewall that denies inbound connections.

First boot

When the desktop loads, the Welcome to RawOS window opens with the safety notes and quick links. It has:

  • Open RawView, to launch the analysis app.
  • Docs, to open this documentation.
  • A Don't show this again checkbox. Tick it and the window stops appearing automatically at login.

You can reopen the welcome window any time from the applications menu (Welcome to RawOS), and this documentation from RawOS Documentation, even after you have dismissed the welcome window.

Tip. The dismiss setting is per user. It is stored at ~/.config/rawos/no-welcome. Delete that file to bring the welcome window back at login.

RawView

Launch RawView from the applications menu or by running rawview in a terminal. Ghidra and the JDK are already installed and configured, so there is no first-run download.

Enabling the AI agent

RawView includes an AI assistant. To use it, open File > Settings and paste your own Anthropic API key. The key is yours; RawOS does not ship one.

Safe detonation

Never run an unknown sample on the RawOS host directly. Detonate inside a disposable guest VM attached to the isolated network.

  1. Open virt-manager from the menu.
  2. Create or import your analysis guest (bring your own Windows image; it cannot be redistributed with RawOS).
  3. Set the guest's network to rawos-isolated. This network has no route to the internet; guests can reach each other and the host only.
  4. Take a snapshot of the clean state.
  5. Detonate, observe, then revert to the snapshot.
Fake internet. To make a sample believe it is online, point the guest at inetsim running on the host. This serves fake DNS, HTTP, and other services so you can watch the sample's network behavior without giving it real reach.

Installing to disk

RawOS boots as a live system. To install it permanently, open Install RawOS from the menu. The installer walks you through:

  • Location and Keyboard, prefilled from the live session.
  • Disk, the target to erase and install onto.
  • Account, your username, password, and computer name.
  • Summary, then it installs with a live progress bar.
The chosen disk is erased. Everything on the target disk is permanently deleted. Double-check the disk on the Summary page before you click Install.

When it finishes, remove the installation medium and reboot into your new system.

Desktop and networking

RawOS uses XFCE themed with Tokyo Night. Change the theme, wallpaper, and panels from Settings. RawView keeps its own in-app theme picker, independent of the desktop theme.

Networking is managed by NetworkManager; use the network icon in the panel to connect. The firewall denies inbound connections by default while allowing your outbound traffic so updates work. Per-analysis isolation is done at the VM level, not on the host.

VM clipboard

When you run RawOS itself as a guest, the SPICE guest agent (spice-vdagent) is preinstalled, so copy and paste between your host and RawOS works once the agent is running. If you are testing with the bundled QEMU launcher, it wires the clipboard channel for you.

Troubleshooting

RawView says the CPU is incompatible with the Qt version

RawView's Qt build needs a modern CPU baseline (x86-64-v2). If you run RawOS in a VM, give the guest a host-passthrough CPU rather than a generic emulated one. Under QEMU, use -cpu host. In virt-manager, set the CPU model to host-passthrough (or copy the host CPU configuration).

No sound in a VM

The OS is audio-ready (PulseAudio and a volume control are installed), but the virtual machine needs an emulated sound card. Add one in your VM settings, or use the bundled launcher which attaches an Intel HDA device.

A website will not load but you are connected

That is usually DNS. Check that /etc/resolv.conf points at the systemd-resolved stub and that the network is managed by NetworkManager.

The desktop went to sleep and things got stuck

RawOS disables automatic sleep, blanking, and locking for analysis sessions. If your VM host suspended the guest, resume it from the host controls.

RawOS is free software built on RawView and open-source tooling. Detonate responsibly, snapshot often, and keep the network isolated.
